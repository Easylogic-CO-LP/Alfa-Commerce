# Alfa Commerce 2.3.0: the names without the prefix

The `alfa-` prefix left the class names, the element ids and the data attributes of the component, the modules and the plugins, storefront and administrator. What scopes a rule is the wrapper or the module root, not a prefix: every component rule is written under `:where(#alfa-app)` (general.css, item.css and stepper.css, which the items, cart and catalog modules load for the component markup they render, under `:where(#alfa-app, .mod-alfa-items, .mod-alfa-cart, .mod-alfa-catalog)`), every module rule under `:where(<module root>)`, at zero specificity. The design tokens (`--alfa-...`), the language keys, the PHP namespaces, the asset names (`com_alfa.*`, `plg_*`, `mod_*`), the table names, the plugin groups (`alfa-payments`, `alfa-shipments`, `alfa-item-fields`, `alfa-form-fields`, `alfa-media`, `alfa-search`), the window events (`alfa-notifications-ready`, `alfa-notifications-changed`), the custom element `<alfa-core-loader>`, the menu type `alfa-storefront` and the module roots (`mod-alfa-filters-wrapper`, `mod-alfa-filters`, `mod-alfa-items`, `mod-alfa-catalog`, `mod-alfa-categories`, `mod-alfa-manufacturers`, `mod-alfa-cart`, `alfasearch-wrapper`) keep their names: they are names of things, not prefixes. A template override written against the old names follows this map.

## Wrapper and structure

| old | new |
| --- | --- |
| `<div id="alfa-app" data-view="...">` (site) | `<div id="alfa-app" class="<page class>" data-view="...">`, the page class set by the view: items-list-page, manufacturers-list-page, orders, userinfo, registration, registration-complete |
| `<div class="com-alfa items-list-page">` and the inner divs of manufacturers, registration, registration complete, userinfo, orders, cart empty, catalogue only | gone; the wrapper carries the page class |
| `<div class="com-alfa item-container" data-item-id>`, `<div class="com-alfa cart-wrapper" ...>`, the order pages, `<section class="com-alfa item-related">`, `<div class="com-alfa cart-added">` | the same element without `com-alfa` |
| `<div class="com-alfa mod-alfa-items ...">` (items module root) | `<div class="mod-alfa-items ...">` |
| administrator screens on Joomla's base view (18 views) and the record edit screens (AlfaFormView) | inside `<div id="alfa-app" data-view="...">` like every other screen |
| `<div class="com-alfa-tools p-3">`, `com-alfa-resetdefaults`, `com-alfa-cleardata` | `tools-page`, `resetdefaults-page`, `cleardata-page` |
| `com-alfa-price-audit com-alfa-audit`, `com-alfa-inventory-audit com-alfa-audit` | `price-audit audit-report`, `inventory-audit audit-report` |
| `.com-alfa ...` selectors (222) | `:where(#alfa-app) ...`; the page classes moved to the wrapper read `:where(#alfa-app.orders) ...`, `:where(#alfa-app.userinfo) ...` |
| rules of the cart-added card and the search panel (appended to the body) | `:where(.cart-added) ...`, `:where(.search-enhance) ...` |
| rules of the administrator bell, sidebar menu, toasts, action frame (injected into Atum) | `:where(.notify) ...`, `#sidebarmenu ...`, `#notification-toasts ...`, `:root[data-action-frame]` (their own roots, outside the wrapper) |
| slider arrows `alfa-slider-arrow`: a round button | `slider-arrow`, `slider-arrow-prev`, `slider-arrow-next`: a plain chevron button, rectangular, radius `--alfa-radius`, no circle, no shadow; the lightbox (GLightbox skin `storefront`, container `glightbox-storefront`) takes the same look |
| GLightbox default skin `glightbox-clean` | `glightbox-storefront` (item.js opens with skin `storefront`) |
| filters module: panel surface and padding in every state | only while the dialog is a modal (`.filters-offcanvas:modal`); inline the module paints no background and adds no padding |
